## 0. Verdict

Overall this is a careful research system:

- The core statistics (PSR, Deflated Sharpe Ratio, Newey-West IC, Bonferroni registry) are **correct**.
- The point-in-time discipline in the qlib engine is better than most student or professional code.
- No XSS, path traversal or command injection was found.
- The paper-trading double-order guard is sound.

The weaknesses come in three groups:

1. **Trust boundaries the system enforces in its own code instead of in the operating system.** The self-fix policy, the lint check and the helm_data objects all fall here.
2. **Read-modify-write on JSON files with no locks**, so research-integrity counters can silently lose updates.
3. **One bootstrap bug** that can flip the "main version" gate.

None of this needs a rewrite. The fix list below is about two to three focused weeks of work.

| Area | Grade | One-line reason |
|---|---|---|
| Statistical methodology | A− | Right formulas; bootstrap edge bias and iid assumption in PSR |
| Research integrity (look-ahead, multiple testing) | B | Engine is excellent; the strategy runtime leaks future data |
| Security | C+ | Strong perimeter, but the agent can grant itself every permission (11-13 self-fix) |
| Persistence / data model | C | Atomic renames but lost updates, no fsync, no schema versions, 2.1 GB of trash |
| Architecture / maintainability | C+ | `server.mjs` and `app.js` are god-modules; tests are good but hand-wired |
| Tests | B+ | 30 files, deterministic and seeded; no coverage numbers, no timeout |

## 2. Algorithms and statistics: detail

### 2.1 Use a circular block bootstrap with a data-driven block length (#2, #7)

```js
// lib/stats.mjs: replace blockBootstrap's inner loop
const L = opts.block ?? Math.max(5, Math.round(Math.cbrt(len)));   // or Politis–White (2004)
for (let i = 0; i < n; i++) {
  let k = 0;
  while (k < len) {
    const s = Math.floor(rnd() * len);                // any start
    for (let j = 0; j < L && k < len; j++) x[k++] = r[(s + j) % len];  // wrap around
  }
  out[i] = stat(x);
}
```

Then fix the shared index-allocation hot path, which currently takes 671 ms in risk mode. Accumulate Σx and Σx² over the resampled indices instead of building `Array.from` arrays. Target: under 250 ms for 3.7k days.

**Validation harness** to keep as a slow test: simulate 1,000 AR(1) paths for φ ∈ {−0.2, 0, 0.2} and n ∈ {252, 756}, then assert coverage and one-sided false-positive rates. `drift.mjs` already has a correct stationary bootstrap you can reuse.

### 2.2 Make PSR/DSR robust to autocorrelation (#6)

Multiply the variance term by the Newey-West long-run factor:

```
den² ← den² · (1 + 2 Σ_{k=1..L} (1 − k/(L+1)) ρ_k),   L = ⌊4 (n/100)^{2/9}⌋
```

This follows Lo (2002) and Bailey & López de Prado (2014). Alternatively, take the standard error from the circular bootstrap so gates ① and ③ share one source of truth.

Also store **Helm's own daily Sharpe** in `trials.jsonl`. Today the trial-variance term mixes LEAN's risk-free-adjusted Sharpe with Helm's Sharpe at rf = 0.

### 2.3 Use sequential monitoring for paper drift (#8)

A 5%/95% band re-checked every day is a repeated-significance-testing problem. Two options:

- **Simplest:** only issue verdicts at fixed checkpoints (20, 60, 120, 250 trading days), with Bonferroni across 4 looks (1.25% per tail).
- **Better:** a Pocock-style constant boundary (≈1%/99% per look) or an alpha-spending function (Lan–DeMets O'Brien–Fleming).

Separately, centre the null on a **deflated** Sharpe. The source backtest is the best of N tries, so its own distribution is optimistic.

### 2.4 One canonical daily-series type

There are three builders today, each with different filters: `stats.dailyEquity`, `robust.prepare` and `paper.daily`. Replace them with one:

```ts
DailySeries { day: Int32Array /* yyyymmdd */, eq: Float64Array,
              bench: Float64Array /* NaN = missing */, r: Float64Array, rb: Float64Array }
```

- Build it once from the market calendar (this fixes #16).
- Cache it keyed by `resultPath:mtimeMs:size`.
- Share it across validate, robust, drift and journal.

This removes a whole class of "two modules disagree on N" bugs and takes the 3.7 MB re-parse off every request.

### 2.5 Smaller items

- **Cost stress:** divide traded value by **start-of-day** equity `eq[idx-1]` (`robust.mjs:155`). Label turnover as two-sided.
- **Two "annual excess" numbers:** arithmetic (stats) vs geometric (robust). Name them differently in the UI.
- **Idea verdicts:** store `t` and recompute the verdict when reading, using the *current* registry threshold. Today a "signal" verdict is frozen at the M of that day.
- **Non-overlapping t-stat:** average over all h start offsets instead of `iloc[::h]`.
- **`regimeLabels`:** rolling sums instead of slice+sort per day. O(n·w log w) → O(n). Not urgent.

## 3. Data model and persistence

### 3.1 As-is

```
projects/<id>/project.json, holdout_log.json (RMW!), *.py, spec.md
  backtests/<32hex>/meta.json (no schema version) code/ (full copy) out/ (3.7–5.2 MB JSON, 0.7 MB order events)
  paper/<sid>/session.json latest.json log.jsonl runs/<date>/
data/trials.jsonl (append-only, dedup on read)   projects/.trash (never cleaned)
```

The problems:

- The invariants carry research weight: ≤1 main per period, holdout looks counted, trials only grow. Yet they are enforced by read-modify-write on JSON files written from **two processes**, the server and every MCP child.
- Temp+rename stops torn files, not **lost updates**.
- There is no fsync and no schema version.

### 3.2 Recommended: SQLite for the rows that carry the invariants

`node:sqlite` is already in your Node 22. Use WAL mode and `busy_timeout = 5000`.

```sql
CREATE TABLE schema_meta(version INTEGER);
CREATE TABLE backtests(id TEXT PRIMARY KEY, project_id INT, role TEXT, period TEXT, status TEXT,
  created TEXT, completed TEXT, summary_json TEXT, fingerprint_json TEXT, code_sha TEXT, result_path TEXT);
CREATE UNIQUE INDEX one_main ON backtests(project_id, period) WHERE role = 'main';
CREATE TABLE holdout_looks(project_id INT, backtest_id TEXT, at TEXT, UNIQUE(project_id, backtest_id));
CREATE TABLE trials(backtest_id TEXT PRIMARY KEY, project_id INT, win_start TEXT, win_end TEXT, sharpe REAL, at TEXT);
CREATE TABLE paper_sessions(id TEXT PRIMARY KEY, project_id INT, source_backtest_id TEXT, mode TEXT, status TEXT, …);
CREATE TABLE paper_runs(session_id TEXT, data_date TEXT, run_at TEXT, ok INT, snap_json TEXT, PRIMARY KEY(session_id, data_date));
```

- `seq` comes from `row_number()`.
- "Only grows" becomes "no DELETE statement exists".
- "One main" becomes a constraint the database enforces instead of code.

**Keep as files:**

- **Code snapshots:** content-addressed under `blobs/sha256/…`.
- **LEAN outputs:** gzip after completion. Also write a small `index.json` (statistics, chart names, order count) so list and read endpoints never touch the 5 MB file.

**If you'd rather not add SQLite yet:**

- Convert `holdout_log.json` to append-only `.jsonl`.
- Add `lib/fs-atomic.mjs` with `writeJsonAtomic` (open → write → `fh.sync()` → rename), `appendLine` (makes sure the file ends in `\n` first, then `datasync`) and `withFileLock` (`open(f+'.lock','wx')` with a stale timeout).
- Add a lint test asserting no raw `writeFile` / `appendFile` under `lib/` outside `fs-atomic.mjs`.

### 3.3 Retention

- Purge `.trash` after 30 days (show the space freed in the UI).
- Keep the `research/quant_runs/*/data/*.pkl` caches for the latest 2 runs per project only.
- Remove `order-events.json` and `log.txt` from runs older than 90 days.
- **Target:** `projects/` under 200 MB after the first sweep, down from 2.2 GB.

## 4. Security: move enforcement to the OS

The 11-13 self-fix design asks the agent to stay inside a policy written in files the agent can edit. That can't hold. Recommended, in order:

1. **Sandbox agent Bash and verify runs.** You already use `sandbox-exec` for LEAN; reuse it. Allow writes only to the free directories. Deny `data/secrets`, `~/.ssh`, `~/Library` and the network.
2. **Alternative:** have agents work in a **git worktree** and apply the diff only after approval plus a passing test run. A mistake then never touches the live tree.
3. **Allowlist instead of denylist.** `lib/` and `mcp/` ask by default. Free means only non-protected parts of `engine/qlib_research/*.py`, *new* test files and `SKILL.md`. Keep a hard list of security files that always ask: `change-policy.mjs`, `agent-perms.mjs`, `mcp/qc-mcp.mjs`, `alpaca.mjs`, `lint_strategy.py`, `engine.mjs#sandboxed`, `test/server-auth*`, `test/sandbox*`, `test/self-fix*`.
4. **Normalise paths:** `fs.realpathSync` on the nearest existing parent, then `.normalize('NFC').toLowerCase()`, compared against lower-cased lists. This also closes symlink tricks.
5. **Remove `git` from the read-only list.** Expose an MCP tool `execFile('git', ['diff', '--', ...validatedRelPaths])` instead.
6. **Count `skipped` as not verified.** Always run the JS fast suite. Editing an *existing* test file asks.
7. **Per-file leases** across concurrent runs, and run `verify` inside `serial()`.
8. **Skill frontmatter:** ask on any key other than `name` and `description` (possible tool grants).
9. **Lock down `helm_data` (#3):** store data under `_` names and reject `obj._x` in lint unless `obj` is `self`. Long term, deliver signals as LEAN `PythonData` custom data so LEAN's clock prevents reading ahead.
10. **Lint (#9):** resolve module aliases, reject non-literal `getattr`/`setattr`, and allowlist `pandas`/`numpy` attributes.

Already good, keep it: the Host allowlist, `timingSafeEqual` token check, Origin and Sec-Fetch-Site checks, CSP with no inline scripts, argument-array spawns, the id regexes, env allowlists for LEAN, and the Alpaca client pinned to the paper endpoint with `redirect:'error'`.

## 5. Architecture

### 5.1 Server: target layout

```
server.mjs                 boot / listen / shutdown                       ≤120 lines
http/router.mjs            table {method, path|re, auth:'ui'|'agent'|'public', schema, handler}  ≤150
http/{security,body,sse}.mjs                                              ≤120 each
routes/{data,actions,qlib,paper,chat,agents,changes}.mjs                  ≤150 each
agents/{prompts,args,runner,pending}.mjs   runner = pure reduce(state, event)  ≤250
store/{threads,fs-atomic}.mjs
```

The key property is that auth and the request schema live **next to the route**. Then one test can list every route and assert that each non-GET route has `auth !== 'public'`. Today the 5 hard-coded exemptions in `checkMutation` and the `REQUIRED` table can drift apart from the routes.

### 5.2 Frontend: ES modules, no build step

The CSP already allows `<script type="module">`.

- `js/core/`: dom, state, router, bus, poll, md, charts.
- `js/views/<route>.js`: each exports `mount(el)`, `render(S)` and `unmount()`. `unmount` removes the listeners and timers `mount` added.

Budgets: ≤600 lines per view, ≤300 per core module.

Payoff: tests `import { md }` directly instead of slicing functions out of `app.js` by marker strings. Also:

- Re-render only the last Markdown block while streaming.
- Add `es.onerror` with backoff and a "disconnected" banner.

### 5.3 Tests

- Move to `node:test`: built in, with `--test-timeout=600000` and `--experimental-test-coverage`. Keep `check()` as a thin wrapper over `assert`.
- Discover test files with `readdirSync(...).filter(f => f.endsWith('.test.mjs'))`.
- Add these regression tests:
  - the 14 `md()` XSS payloads
  - lint bypasses
  - helm_data future-data access
  - policy case variants, `git diff --output`, an agent-written `test_*.py`
  - concurrent holdout tags
  - kill -9 fuzz on `.jsonl`
  - the bootstrap coverage harness (slow tier)
- **Target:** ≥70% line coverage on `lib/`, and a full fast suite under 30 s wall time (currently 42 s, of which only 9 s is CPU).

## 7. Things done well

1. **The statistics are right where it matters:**
   - PSR and DSR use raw kurtosis, √(n−1) and the correct expected-max SR₀.
   - Newey-West lag is `max(2h, 10)`.
   - The Bonferroni registry is updated *before* evaluation.
   - Quintile spreads are net of two-sided turnover cost.
   - The risk-adjusted test bootstraps paired days, so strategy–benchmark correlation is preserved.
2. **Point-in-time care in the qlib engine:**
   - Earliest-filed fundamentals become available the day after filing, with a truncation audit.
   - Walk-forward splits keep h+1-day gaps, checked by `check_no_overlap`.
   - Expressions that need future data are rejected.
3. **Honest bookkeeping:**
   - The trial ledger is append-only, ignores labels and counts across projects.
   - Deleting a backtest doesn't reduce the attempt count.
   - LEAN-vs-equity-curve consistency checks guard against bad numbers.
4. **Paper-trading safety chain:**
   - Deterministic `client_order_id`s.
   - Skip the day on stale data.
   - Cancel and settle own orders before counting.
   - Touch only the session's own positions.
   - Alpaca pinned to the paper endpoint.
5. **Engineering hygiene:**
   - Seeded RNGs everywhere and temp-dir tests.
   - Escape-first Markdown with a strict CSP.
   - Argument-array spawns and consistent id validation.
   - An mtime-keyed validation cache that refuses to cache when the key changes while computing.
